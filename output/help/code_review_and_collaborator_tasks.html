Review date: 2026-09-13. Scope: the six exported functions, their internal helpers, registered S3 methods, existing tests, vignette, and package build. Reviewed development version: 0.0.0.9000 in Documents/ALRD. The GitHub checkout was not used as the source of this review.

Assessment

The package contains a useful working prototype of longitudinal direct and augmented learning. It is ready for controlled development examples with a complete numeric basis, positive subject-constant weights, and admissible correlation settings. It is not yet ready for broad scientific use or a JSS submission: prediction contracts, covariance checks, and full-pipeline validation need work. Passing the existing tests does not establish statistical validity across the public API.

The reference article, Huling and Yu (2021), Subgroup Identification Using the personalized Package, JSS 98(5), DOI 10.18637/jss.v098.i05, organizes its software section around the complete user workflow. ALRD currently implements the fitting core but lacks much of that diagnostic and validation workflow. Its multi-treatment and multiple-outcome features should not be copied simply to match the reference paper’s breadth.

This is an implementation review, not verification of the ALRD method paper’s theorems or a new simulation study. The referenced ALRD methodology paper was not supplied in this task. In particular, two-stage weighting alone does not justify an unconditional claim of double robustness for every fitted basis, penalty, covariate history, and covariance specification.

Findings requiring implementation work

P1: Preserve prediction encoding and row count

In R/predict_ite.R, both methods reconstruct a model matrix from stored terms without stored training factor levels and contrasts. They then index the coefficients by new matrix column names. Reordered levels can change the reference category and request nonexistent coefficients. Missing covariates are checked, but missing values are not, allowing rows to disappear.

Store the training levels, contrasts, and design-column schema. Validate new levels explicitly, align the new design to the training columns, and define an NA policy that either errors or returns an NA in the original row position. Add a test where prediction on the same values with reordered factor levels is unchanged, plus tests for single-level subsets, novel levels, and missing rows.

P1: Resolve zero weights and covariance domain validation

.fit_gls() drops zero-weight rows internally while the fitted-object metadata and correlation-update inputs retain all rows. This can shorten residuals and misalign subsequent rho updates. Decide whether zero weights mean explicit exclusion or retained rows with zero contribution; preserve a row map and consistent outputs under that decision.

.default_rho() checks only a generic interval, while exchangeable correlation also requires ρ>−1/(m−1)\rho > -1/(m-1) for every subject. The residual updater clamps to [-0.95, 0.95], which does not ensure that condition. .correlation_matrix() allows duplicate AR(1) times and negative rho with fractional lags. Validate finite times, unique subject-time pairs, positive definiteness, and admissible rho before solving; constrain iterative updates to the same valid domain.

P1: Specify weights before extending the statistical claims

In .fit_gls() and .transform_gls(), the Cholesky factor CC, satisfying C𝖳C=V−1C^{\mathsf{T}}C = V^{-1}, is applied first, then W1/2W^{1/2}. The quadratic form is

𝐞𝖳C𝖳WC𝐞. \mathbf{e}^{\mathsf{T}} C^{\mathsf{T}} W C \mathbf{e}.

It equals the intended scalar subject-weighted form when WW is constant within subject. It does not generally equal

𝐞𝖳W1/2V−1W1/2𝐞. \mathbf{e}^{\mathsf{T}} W^{1/2} V^{-1} W^{1/2} \mathbf{e}.

Neither arbitrary-row-weight extension should be called correct without a defined estimand and loss.

For the first release, consider requiring subject-constant propensity and analysis weights for the baseline-treatment objective. Otherwise write the intended row-weighted objective and derive a matching solver before changing weight placement. Keep the direct GLS oracle test for the supported case.

P1: Validate the complete two-stage pipeline

fit_alrd() computes the main-effect predictions and residualized response before the ITE-stage .fit_lasso_gls() call. Each stage’s glmnet folds preserve subjects, but ITE validation outcomes have already influenced the full-sample main-effect fit. Automatic propensity estimation and rho estimation also use the full fitting sample. Clustered folds alone do not provide a held-out evaluation of the entire procedure.

Add outer subject splits and estimate the propensity model, augmentation, working correlation, selection, and refit from each training split only. Specify whether tuning and final performance evaluation use distinct nested layers. Decide with the method lead whether cross-fitting is also required for the estimator itself; that is a separate methodological choice from honest testing.

P1: Enforce the baseline-assignment and rank contracts

The public fit functions accept treatment changes within a subject, although their stated model uses a single T_i. The existing first two tests and original vignette used row-varying treatments. Replace those examples/tests with the intended design and add explicit unsupported-design checks.

Automatic ALRD propensity estimation fits the treatment on all visits using the outcome basis, including time if supplied. This is not automatically a baseline-confounder model. With unequal visits it also gives greater likelihood weight to subjects with more rows. Provide separate propensity covariates or a subject-level score interface. Decide an explicit common default for ps across the two fit functions rather than silently assuming observational or randomized assignment.

QR fitting can return NA coefficients for aliased columns; multiplication by that coefficient vector can make all predictions NA. Decide whether to reject rank deficiency or support estimable predictions with a documented alias policy.

P2: Finish solver controls and diagnostics

  • Require at least three folds for the current glmnet workflow; validate integer nfolds, rho_max_iter, simulator n/scenario, and logical controls explicitly.
  • Separate tuning controls for augmentation and ITE; expose lambda.min versus lambda.1se as a deliberate policy. Record fold IDs for reproducibility.
  • Use explicit intercept identity rather than matching any column name containing “Intercept” to decide penalty exemptions.
  • Distinguish selected columns, intercept inclusion, and original variables. Forced intercept inclusion during refit may differ from selected_terms when its penalized coefficient is numerically zero.
  • Warn on failed correlation convergence and expose fitting diagnostics through dedicated summary methods. A generic list summary is not a model summary.
  • Add row/data validation for Inf, empty data, missing treatment, and treatment level counts. Existing complete.cases() checks do not reject Inf.
  • Consolidate duplicated GLS and prediction code. Preallocate transformed matrices rather than growing them with repeated rbind(). Profile before selecting performance targets or claiming speed improvements.

Documentation delivered in this review

All six exported function help pages now define parameters, return values, examples, coding conventions, and known limitations. A package overview and shared print-method topic were added. The introductory vignette was rewritten with baseline treatment, subject holdout, both fitting paths, lasso, covariance inspection, ITE trajectory prediction, and baseline propensity mapping.

The usage guide now uses the actual simulator column propensity (previously incorrectly ps) and the actual nested rho_estimation fields. AR(1) uses actual time gaps; supplied rho can be estimated when explicitly requested; the lasso applies to both stages. New-data and validation limitations are explicit.

The browsable manual is generated by scripts/build_help.R into output/help/. Help examples are executable, and the rendered vignette contains real generated output. R source edits in the six existing function files are documentation comments only; estimator bodies have not been altered by this review.

Build exclusions were added for local agent instructions, manuscript, output, scratch files, and development scripts. Scripts remain in the repository and must be included separately in the JSS replication bundle where appropriate.

Manuscript and repository follow-up

The earlier manuscript needs the same corrections before circulation: AR(1) uses actual time differences, complete-case data are required rather than automatically selected, and clustered glmnet folds do not constitute complete two-stage validation. Its robustness paragraph needs the actual method-paper citation and conditions. This task did not regenerate that PDF.
